# Prioritized Remediation Plan & Engineering Roadmap

Audit date: 2026-11-03. Audited commit: `ace6bb0` (`main` branch).
**Status**: Proposal only — no application code has been modified. Implementation begins only after review and explicit sign-off.

Effort sizing: **S** ($\le 0.5$ day), **M** ($1\text{–}2$ days), **L** ($\ge 3$ days). Test IDs reference [`TEST_COVERAGE.md`](TEST_COVERAGE.md).

---

## Core Engineering & Statistical Principles for Remediation

1. **Fail Loudly Instead of Rewriting User Constraints Silently**: Infeasible budgets, missing/misspelled plan columns, duplicate `(date, channel)` rows, and panels shorter than `2 × holdout_days` must raise explicit HTTP 422 validation errors with actionable guidance—never silently scale bounds, zero-fill paid channels, or substitute training metrics for hold-out metrics.
2. **Single Immutable Configuration per Run Execution**: Once a run leaves `"draft"` status, its `config` is frozen. Re-running with modified settings must occur atomically via a dedicated endpoint (or create a new run version), purging or versioning downstream forecasts, scenarios, optimisations, and worker caches.
3. **Data-Driven Narrative Generation**: Every qualitative executive claim (`"Yes — below 15%"`, `"Meridian beats OLS-2"`, `"Catalog ROI ≈ 1"`, green `"success"` badges on optimiser lifts) must be branched dynamically on the computed posterior statistics and causal caveats.
4. **Honest Ex-Ante Evaluation & Uncertainty Quantification**: Separate ex-post accuracy (with realised Affiliate commission and SEA spend) from ex-ante budget-plan accuracy, compute horizon prediction intervals from draw-level sums rather than sums of daily quantiles, and surface $\mathbb{P}(\text{ROI} < 1)$ and prior-vs-posterior shrinkage ratios alongside point ROI estimates.
